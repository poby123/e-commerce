# ADR-0002 하이브리드 Saga

- 상태: 채택 (2026-10-07)

## 결정
- **주문 → 쿠폰 → 재고 → 결제**: order-service 안의 `OrderSaga`가 오케스트레이션한다. 명령/응답은 Kafka, Saga 상태는 `order_saga` 테이블에 저장한다.
- **부수 효과**(알림, 가입/첫구매 쿠폰 지급, 검색 인덱스): `OrderCompleted`, `UserRegistered` 같은 이벤트를 구독하는 코레오그래피로 처리한다.

## 이유
- 둘 다 보상(롤백)은 가능하다. 차이는 흐름을 보고 바꾸는 비용이다. 참여 서비스가 4개이고 쿠폰처럼 단계가 계속 늘 수 있으므로, 흐름을 한곳에서 보고 수정할 수 있는 오케스트레이션을 택했다. 코레오그래피였다면 쿠폰을 추가할 때 inventory·payment·order를 모두 고쳐야 했다.
- 실패해도 주문을 되돌릴 필요가 없는 작업은 주문 흐름이 알 필요가 없으므로 이벤트로 분리한다.

## 세부 규칙
- 순서: 실패 가능성이 높고 되돌리기 쉬운 단계(쿠폰)를 앞에, 되돌리기 어려운 단계(결제)를 맨 뒤에 둔다. 보상은 역순으로 실행한다.
- 격리성: 쿠폰은 `ISSUED → RESERVED → USED`(Semantic Lock / TCC 형태)로 관리한다. 예약 중인 쿠폰은 다른 주문이 쓸 수 없다.
- 멈춘 Saga: 타임아웃 스케줄러가 재시도하거나 보상을 실행한다.
- 외부 PG는 Outbox로 묶을 수 없다. 멱등키(sagaId)와 결과 조회 API로 처리한다.
