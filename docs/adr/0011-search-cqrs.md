# ADR-0011 상품 검색: Elasticsearch 읽기 모델 (CQRS)

- 상태: 채택, 구현 완료 (2026-10-07). 하이브리드(벡터) 검색은 6b에서 결정
- 재현: `scripts/seed-products.sh` → `scripts/demo-reindex.sh`

## 구조
```
product-service ─[tx] products + outbox(ProductChanged, 전체 상태 + version)─▶ Debezium ─▶ product.events
                                                                                         │
search-service ◀─────────────────────────────────────────────────────────────────────────┘
   └─ ES "products" alias ─▶ products-<timestamp> (Nori, 사용자 사전, 동의어, 자동완성 필드)
   GET /api/search/products, /api/search/autocomplete (공개)   POST /internal/search/reindex (운영자)
```

## 결정과 이유
| 결정 | 이유 |
|---|---|
| Elasticsearch 8.18 + Nori | 국내 커머스 표준이고 한국어 형태소 분석을 공식 지원한다. 서버 버전은 Boot 3.5가 관리하는 클라이언트(8.18)에 맞췄다. 클라이언트가 서버보다 높으면 호환이 보장되지 않는다 |
| 이벤트에 **전체 상태 + version** | 변경분(diff)만 보내면 하나만 유실돼도 영원히 어긋난다. 전체 상태면 마지막 이벤트만 반영돼도 맞춰진다 |
| 상품 version = ES **external version** | ES가 같거나 낮은 버전을 스스로 거부한다. 중복·순서 역전 이벤트가 무해하므로 search-service에 DB도 processed 테이블도 필요 없다 |
| 무중단 재색인: `products`(읽기) + `products-building`(재구축 중) alias | 재구축 중에는 실시간 이벤트를 양쪽 인덱스에 쓰고, 전체 백필은 external version으로 쓴다. 백필 도중의 변경이 더 최신이라 이긴다. 마지막에 alias를 원자적으로 교체한다 |
| 다중 선택 facet: post_filter + 필터별 집계 | 브랜드 A를 골라도 브랜드 목록에는 B, C의 개수가 남는다. 각 facet은 자기 필터를 뺀 나머지 필터만 적용한다 |
| 정렬 동점은 productId로 | 같은 점수끼리 순서가 고정되지 않으면 페이지를 넘길 때 상품이 반복되거나 빠진다 |
| 깊은 페이지 제한(page × size < 10,000) | ES의 `max_result_window`. 무한 스크롤이 필요하면 `search_after`로 바꾼다 |

## 한국어 분석에서 실제로 부딪힌 것
| 문제 | 원인 | 조치 |
|---|---|---|
| "초음파가습기" → 초음파 / 가 / **습기** | Nori 기본 사전에 "가습기"가 없다. "습기 제거제"까지 검색된다 | 사용자 사전에 등록. 테스트로 고정(가습기 검색 시 습기 제거제가 나오지 않음) |
| 동의어 등록 시 인덱스 생성 실패 | "이어셋"이 이어(동사) + 셋으로 분석되고, 품사 필터가 "이어"를 지워 위치가 빈 토큰이 남았다 | **동의어에 쓰는 단어는 사용자 사전에도 넣는다**를 규칙으로 정함 |
| "스니커즈" 검색이 "운동"으로 확장 | 동의어 "운동화"가 운동 + 화로 분석됐다. 그대로면 "운동복"까지 걸린다 | 같은 규칙으로 해결 |
| 자동완성 "무선충" 실패 | 입력 중인 글자를 Nori가 무선 + 충으로 다시 쪼갰다 | 자동완성 검색어는 형태소 분석을 하지 않는다 |
| 자동완성 "무선블루" 실패 | 저장은 형태소 단위 접두사인데, 입력은 띄어쓰기 없이 여러 단어에 걸쳐 있었다 | 공백을 제거한 이름 전체의 접두사 필드(`name.prefix`)를 추가해 두 필드 중 하나만 맞아도 제안 |

사전과 동의어는 매핑의 일부라서 바꾸면 **재색인이 필요하다**. 위 무중단 재색인이 그 운영 절차다.

## 검증
| 항목 | 결과 |
|---|---|
| `ProductSearchTest` (Nori 이미지 Testcontainers) | 7개 통과: 복합어, 사용자 사전, 동의어, 다중 facet, 오래된/중복 이벤트, 판매중지, 자동완성 4가지, 재색인 중 변경 보존 |
| E2E (`smoke-test.sh`) | 상품 등록 후 **0.9~2.2초** 안에 검색됨, 가격 변경 반영, 판매중지 시 사라짐 |
| 무중단 재색인 (`demo-reindex.sh`) | 36건 3.6초. 재색인 중 검색 56건 **모두 200**. 그사이 4번 바꾼 가격은 마지막 값(44,000)으로 DB와 인덱스가 일치 |
| 트레이스 | 상품 수정 → product-service → Outbox/Kafka → search-service가 하나의 트레이스 |

## 남은 것
- 재색인은 인스턴스 안의 잠금만 쓴다. search-service가 여러 대면 ES 기반 잠금이나 별도 잡으로 옮겨야 한다.
- 자모 단위 자동완성("무선ㅂ")은 지원하지 않는다(자모 분해 필터 필요).
- 판매량·리뷰 같은 랭킹 신호가 없다. 지금은 BM25 점수와 정렬 옵션만 있다.
- 하이브리드(벡터) 검색은 임베딩 모델 선택이 필요하다(6b).
